## 今天为什么学这个（20 分钟）

这是你的建议接续点。代码显示路由、依赖、日志和 ORM 雏形已存在，但“数据库已建表”和“设备 CRUD 已落库”是两个不同事实。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 按衔接实验的 PowerShell 请求创建一台设备并记住 ID

2. 重启开发服务器，再查同一设备，解释为何内存数据消失

3. 逐项验证 401、404、422、日志 ID，并登记纯空格名称校验问题

## 观察结果与验收（10 分钟）

保存一份真实验收记录；会的跳过，不会的回对应天；不因为代码文件存在就将 Day 1～13 全部标成完成。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

从根目录和 backend 分别解析 app.db 绝对路径但不导入建表模块，识别两个数据库文件来源。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。

## 独立练习与自测

用五句话解释从请求 JSON 到响应 JSON 的链路。指出当前链路中数据库缺席的位置。

先写自己的解释，再对照概念段和官方资料。能复述定义但无法解释实验现象，进度仍标为「练习中」。
