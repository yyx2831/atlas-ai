## 今天为什么学这个（20 分钟）

OOM 可能发生在加载权重或请求运行期，处理方法不同。练习应在独占测试环境有明确资源上限，不能把共享 GPU 故意跑崩。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

2. 有独占测试资源时逐步提高上下文或并发并设置停止阈值，记录失败阶段

3. 按减上下文、减并发、小模型、兼容量化、合理显存预算逐项恢复

## 观察结果与验收（10 分钟）

记录至少一次恢复成功与前后配置；未实机触发时明确标为模拟，不伪造 GPU 日志。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

让客户端对 OOM 无限重试的 mock 场景运行到预算上限，改为可控失败与提示。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
