## 今天为什么学这个（20 分钟）

中间件包围请求链，适合关联 ID 与计时。ContextVar 是上下文局部值，跨线程和中间件顺序需要实际验证，不能假设自动双向传播。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 阅读 core/middleware.py，标出进入和退出顺序

2. 对比 /health 与同步端点的 request_id，在响应头和日志同时记录

3. 使用 perf_counter 测耗时，并在 finally 清理自己设置的 ContextVar token

## 观察结果与验收（10 分钟）

并发十个请求的 ID 不串用，耗时非负；已知同步端点 ID 空值问题单独记录，不把它认定为已修复。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。
