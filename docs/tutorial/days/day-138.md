## 今天为什么学这个（20 分钟）

名字解析失败先查在哪个网络空间发生。宿主 DNS 正常不能证明容器 DNS 正常，服务名称也只在对应网络有效。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 分别在宿主和 API 容器解析数据库服务名

2. 检查 /etc/resolv.conf 和 Docker 网络归属，记录实际查询结果

3. 使用错误服务名复现，再恢复 Compose 的正确名称

## 观察结果与验收（10 分钟）

可以区分 DNS 失败与解析成功后连接失败，避免把数据库密码问题当 DNS。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

把两个测试容器放到不同网络，观察服务名不可解析，接回预定网络恢复。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
