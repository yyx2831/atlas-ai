## 今天为什么学这个（20 分钟）

容器拥有自己的回环地址，同一用户自定义网络内可用服务名解析。API 访问数据库使用容器端口，不是宿主机发布端口。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 在测试网络启动 api、postgres、redis，记录网络名称

2. 将数据库地址设为 postgres:5432，Redis 设为 redis:6379

3. 从 API 容器做 DNS 与 TCP 检查，再调用真正的数据库查询

## 观察结果与验收（10 分钟）

应用可连到数据服务，即使数据库没有发布宿主机端口；知道宿主机访问路径与容器访问路径不同。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
