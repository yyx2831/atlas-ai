## 今天为什么学这个（20 分钟）

容器日志来自标准输出和错误，inspect 给出配置和退出状态，exec 适合检查活着的容器；已经退出的容器无法正常 exec。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 对测试 API 使用 docker logs --tail 100 和 docker inspect

2. 查看容器内工作目录与环境变量名，输出时隐藏值中的密码

3. 在隔离配置中改错数据库主机，比较退出、健康失败和请求时报错三种状态

## 观察结果与验收（10 分钟）

能够由时间、ExitCode、健康状态和日志判断故障层，不仅凭 docker ps 看名字。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

使用错误入口命令产生启动失败，通过 logs/inspect 还原原因，恢复后验证 health。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
