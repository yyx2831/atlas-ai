## 今天为什么学这个（20 分钟）

TLS 加密连接并验证服务器身份，证书的域名和信任链必须匹配。自签名适合受控实验，不应让用户习惯忽略证书警告。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 在测试域名或本地受信任实验 CA 下准备证书与私钥

2. 配置 Nginx 443 与 HTTP 跳转，私钥设置最小读取权限

3. 使用 curl -v 或浏览器证书面板检查域名、有效期、颁发者和链

## 观察结果与验收（10 分钟）

有效客户端无需跳过验证即可访问；记录证书更新方式，不把私钥提交到仓库。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

用错误主机名访问实验服务，观察域名不匹配；改正确名称恢复，不以 -k 作为修复。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
