## 今天为什么学这个（20 分钟）

业务 Agent 依赖统一工具接口，adapter 把远端发现、调用和错误映射回内部格式。工具名称冲突和服务来源必须显式处理。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 给 MCP 工具加服务命名空间，避免与本地同名函数混淆

2. 将 schema 转给模型，将 call_id 与远端请求关联

3. 使用相同 mock 问题对比本地工具和 MCP 工具结果

## 观察结果与验收（10 分钟）

切换传输后业务答案等价，远端超时被映射成明确工具错误。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

断开 MCP server，确认 Agent 不编造成功结果，重连后可重新发现能力。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
