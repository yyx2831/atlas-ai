## 今天为什么学这个（20 分钟）

REST 用资源和方法表达行为，状态码表达结果。当前内存存储只服务单进程演示，重启丢数据是其性质，不是数据库失效。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 关闭参考答案，写出五个设备端点的输入、返回与错误码

2. 在 /docs 带演示 token 完成创建、列表、单查、修改、删除

3. 再次查询删除项，再重启开发服务检查内存数据

## 观察结果与验收（10 分钟）

能独立完成 201→200→200→204→404；知道现有 PUT 实际做局部更新，后续可改 PATCH 或明确定义 PUT 语义。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

遗漏 token 后先得到 401，补 token 后才验证业务错误，理解依赖先于业务校验的影响。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
