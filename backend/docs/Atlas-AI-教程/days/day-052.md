## 今天为什么学这个（20 分钟）

上传、解析、切块、embedding 和写向量不是一个天然原子事务。状态机与幂等 ID 让失败能重试，不能一次 HTTP 超时就丢失工作。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 设计 queued、parsing、embedding、indexed、failed 状态及错误原因

2. 将文档哈希、解析版本、块序号组成稳定 chunk_id

3. 上传接口先存原文和任务记录，再由受控任务执行流水线，重复上传采用明确定义的去重策略

## 观察结果与验收（10 分钟）

同一个任务重试不产生重复点；失败任务可查到阶段，只有全部写完才标 indexed。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

在 embedding 第三批模拟超时，重试后比较点数与块数，验证无重复。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
