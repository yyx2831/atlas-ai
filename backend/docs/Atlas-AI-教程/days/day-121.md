## 今天为什么学这个（20 分钟）

JSON 日志让字段可查询，message 保留人类可读信息；请求 ID 应作为字段而不是只能从字符串里截取。日志 schema 稳定才能建立监控查询。

把今天的知识放回 Atlas：你要交付的是下面这组能复现的行为，而不只是记住术语。实验使用虚构设备与测试数据，路径以仓库根为基准；Bash 与 PowerShell 的区别见环境说明。

## 跟着完成（70 分钟）

1. 统一 timestamp、level、request_id、route、status、duration_ms 与 error_code

2. 将既有 logger 接到 JSON formatter，异常保留结构化堆栈但脱敏

3. 连续发成功、校验失败、内部错误三类请求

## 观察结果与验收（10 分钟）

每行都是独立合法 JSON，字段类型稳定；身份字段只记录业务需要的标识。

保存输入、实际输出、使用的版本和耗时。实际结果不符合预期时，先保留原始错误，再检查本日涉及的配置与数据；不要同时修改多个变量。

## 故障实验（15 分钟）

插入不可 JSON 序列化对象，确认 formatter 处理或拒绝并修正调用点。

完成后撤销故障注入，重复正常路径。涉及删除、停服务、断网、OOM 的实验只在可恢复的隔离测试环境执行；没有条件时用模拟错误，不对正在使用的系统操作。
